# Карманный математический инженер для зала

Telegram-бот на aiogram 3. Без регистрации пользователей — всё считается на лету. Работает как вход в канал: кнопка канала под каждым результатом, подпись канала и бота на карточках, inline-режим для шаринга.

## Файлы

- `bot.py` — хендлеры: меню, пошаговые сценарии, быстрые команды, карточки
- `wizard.py` — сценарии калькуляторов (шаги, кнопки, проверка ввода) и тексты результатов
- `calculators.py` — вся математика (можно тестировать без Telegram)
- `design.py` — дизайн-система «Журнал»: цвета, шрифты, кегли, отступы и блоки карточек
- `cards.py` — состав карточек (только раскладка, без цветов и пикселей)
- `storage.py` — аналитика в SQLite (`bot.db`): user_id, источник, даты, тип действия. Веса и параметры тела не сохраняются
- `webapp/` — мини-приложение (HTML/CSS/JS, без сервера): `calc.js` — формулы, перенесённые из `calculators.py` один в один, `card.js` — карточка на canvas, `app.js` — экраны и Telegram SDK
- `tests/` — сверка формул JS и Python: `python tests/make_fixtures.py`, затем `node tests/parity.test.mjs`
- `.github/workflows/pages.yml` — тесты и публикация `webapp/` на GitHub Pages
- `fonts/` — Inter и IBM Plex Mono (SIL OFL 1.1, лицензии рядом)
- `assets/avatar/` — аватар бота, 3 варианта (SVG + PNG 640×640)
- `previews/` — превью всех карточек на тестовых данных
- `scripts/` — `make_previews.py`, `make_avatars.py`, `check_contrast.py`
- `requirements.txt`, `env.example`

## Дизайн-система «Журнал»

Карточка — страница тренировочного дневника, записанного ручкой: тёплая «бумага», тонкие линейки, точки-лидеры, синие «чернила» на главном. Оценки помечены «≈». Никаких эмодзи и иконок — только цифры.

| Токен | HEX | Контраст к фону |
|---|---|---|
| Фон (бумага) | `#F2EFE8` | — |
| Основной текст | `#141414` | 16.0 |
| Вторичный текст | `#55534D` | 6.7 |
| Подписи | `#615E58` | 5.6 |
| Акцент (чернила) | `#2B44D1` | 6.4 |
| Норма / внимание / плохо | `#1A6B40` / `#8A4E00` / `#B3262D` | 5.7 / 5.8 / 5.7 |

- Цифры и подписи — IBM Plex Mono, текст — Inter.
- Карточка 1080×1350 (4:5), поля 72, отступы кратны 8, клетка 54, скруглений нет.
- Карточка уходит фото (видно прямо в чате), оригинал — кнопкой «Файл без сжатия».
- Все значения — только в `design.py`. Проверка контраста: `python scripts/check_contrast.py`.
- После правок дизайна: `python scripts/make_previews.py` — перерисует превью и упадёт, если что-то налезло на подвал.

## Новый бот с нормальным username

1. В [@BotFather](https://t.me/BotFather): `/newbot` → имя «Математика зала» → username (должен заканчиваться на `bot`).
2. Новый токен — в `.env` (`BOT_TOKEN=...`). Код менять не нужно: username подтягивается сам.
3. В BotFather там же:
   - `/setinline` → выбрать бота → подсказка `вес повторы` (включает `@бот 100 8` в любом чате);
   - `/setdescription`, `/setabouttext`, `/setuserpic` — тексты из инструкции.
4. Старого @Beta_testjdhudbot остановить (или удалить через `/deletebot`), чтобы не было двух ботов.

## Метки источников

Ссылка `https://t.me/<бот>?start=<метка>` запоминает, откуда пришёл человек (только первое касание). Метка — латиница/цифры/`_`, до 64 символов. Примеры: `tt_v1` (TikTok, ролик 1), `yt_v2` (Shorts), `vk_v3` (VK Клипы), `ch_pin` (закреп в канале).

`/stats` или `/stats 30` — сводка за 7/30 дней: новые, активные, источники, действия. Работает только для `ADMIN_ID` из `.env`.

## Запуск локально

1. Получи токен у [@BotFather](https://t.me/BotFather): `/newbot`, следуй инструкциям.
2. `python3 -m venv venv`, затем активация: Windows PowerShell — `venv\Scripts\Activate.ps1`, Linux/macOS — `source venv/bin/activate`
3. `pip install -r requirements.txt`
4. Скопируй `env.example` в `.env` и вставь токен: Windows — `copy env.example .env`, Linux/macOS — `cp env.example .env`
5. `python3 bot.py`

Бот стартует через long polling — виснет в терминале и работает, пока процесс жив.

## Деплой (чтобы работал 24/7)

Варианты по возрастанию сложности:
- **Систематический процесс на своём VPS**: закинуть на сервер, поднять через `systemd` или `screen`/`tmux`.
- **Railway / Render / Fly.io**: задеплоить как worker-процесс (не web-сервис — это long polling, HTTP-порт не нужен), переменную `BOT_TOKEN` — в Secrets/Environment.
- **Webhook вместо polling**: если ожидается много пользователей одновременно — но для одного канала на пару тысяч подписчиков polling более чем достаточен и проще в поддержке.

**Запускай ровно одну копию.** Ошибка `Conflict: terminated by other getUpdates request` в `bot.log` значит, что бот с тем же токеном запущен в двух местах (например, ноутбук + сервер) — одна копия выкидывает другую. На сервере `bot.db` должна лежать на постоянном диске, иначе статистика обнулится при каждом деплое. На Railway: сервис → Settings → Volumes → добавить Volume с путём монтирования `/data`, а в Variables задать `DB_PATH=/data/bot.db`.

## Как устроено меню

```
/start ─ Калькулятор зала
         ├─ Сила ─────────── Разовый максимум · Максимум по RPE · Разминка
         ├─ Пауэрлифтинг ─── DOTS и Wilks · Разряд ЕВСК
         ├─ Тело и питание ─ FFMI · КБЖУ
         ├─ Открыть калькулятор (мини-приложение)
         └─ Канал автора
```

- Калькулятор задаёт вопросы по одному, с примером ввода; пол, повторы, RPE, гриф, активность, цель — кнопками.
- Вес, рост, пол, возраст запоминаются до перезапуска бота: кнопка «Как в прошлый раз».
- Бот редактирует одно сообщение, а не шлёт новые; ответы-числа пользователя удаляет.
- Под каждым экраном «⬅️ Назад» и «🏠 Меню». Результат: цифра, 1–2 строки, кнопки «Карточка», «Посчитать ещё».
- Любая команда прерывает начатый сценарий. Непонятный текст — подсказка и меню.
- При старте бот сам ставит меню команд, описание и кнопку «Открыть калькулятор» (`WEBAPP_URL`).

## Мини-приложение

Адрес: https://andrey0959.github.io/fit_bot/ — открывается кнопкой «Открыть калькулятор» у поля ввода и в главном меню бота.

- Все расчёты на телефоне, сервер не нужен. На Deployka мини-приложение не добавляет ничего.
- Тема берётся из Telegram (светлая/тёмная), главная кнопка и «Назад» — нативные, вибро на нажатиях.
- Пол, вес, рост, возраст, % жира, активность, гриф сохраняются в CloudStorage Telegram.
- Карточка рисуется на canvas в том же стиле: «Поделиться», «Сохранить PNG» и «Прислать карточку в чат» — бот получает ссылку `?start=c-…`, сам считает и присылает картинку.
- Каждый push в `main` с изменениями в `webapp/`, `calculators.py` или `tests/` запускает сверку JS с Python; если цифры разошлись хоть на копейку — сайт не обновится.
- Изменил формулу в `calculators.py` — поменяй и `webapp/calc.js`, иначе тест упадёт.
- Ссылка на конкретный калькулятор: `https://andrey0959.github.io/fit_bot/?tool=kbju` (ключи: 1rm, rpe, warmup, dots, rank, ffmi, kbju).

## Функции

| Команда | Формат | Что считает |
|---|---|---|
| просто `100 8` | вес, повторы | 1RM (Epley/Brzycki/Lombardi) + раскладка 60-95% |
| `/dots` | `м 90 500` | DOTS |
| `/wilks` | `ж 62.5 280` | Wilks |
| `/ffmi` | `180 85 15` | FFMI + нормализованный FFMI |
| `/kbju` | `м 30 180 85 3 сушка` | Калории (Миффлин-Сан Жеор) + БЖУ |
| `/rpe` | `140 3 8` | Оценка 1ПМ по RPE + веса на другие RPE |
| `/warmup` | `140` (или `140 15` — свой гриф) | Лестница разминки до рабочего веса |
| `/rank` | `м 90 500` | Разряд ЕВСК (классическое троеборье) и сколько до следующего |
| `@бот 100 8` | в любом чате | Inline-режим: 1RM прямо в переписке |

Быстрые команды отвечают так же, как меню. К каждому результату — кнопка «Карточка»: PNG 1080×1350 в стиле «Журнал».

## Что доработано против исходной идеи (минусы, которые я закрыл)

1. **Неоднозначность парсинга.** Если бы бот пытался угадывать, что означают два числа (1RM или DOTS), был бы риск неверного распознавания. Поэтому быстрый путь «два числа без команды» жёстко закреплён только за 1RM — самым частым кейсом «между подходами»; остальное через явные команды.
2. **Реалистичность формул на больших повторах.** 1RM-формулы сильно врут после ~12 повторов — бот теперь предупреждает об этом отдельной строкой, а не выдаёт ложную точность.
3. **Практичность весов на штанге.** Рабочие веса в % округляются до шага 2.5 кг (типичный блин), а не до сферической десятой доли килограмма, которую невозможно набрать блинами.
4. **Формат чисел.** Принимает и точку, и запятую (`82.5` / `82,5`) — стандартная боль ру-инпута.
5. **DOTS клампится по весу тела** в границы, для которых формула вообще валидна (иначе на экстремальных весах коэффициент даёт бред).
6. **FFMI — явная оговорка**, что результат насколько точен, насколько точно замерен % жира (а его почти никто не мерит точно) — иначе люди делают далекоидущие выводы из числа с плюс-минус трамвайной остановкой погрешности.
7. **КБЖУ:** белок/жир считаются от веса тела (а не фиксированным % от калорий, как часто делают криво), углеводы — по остатку. Так БЖУ не гуляют произвольно при смене цели.
8. **Отсутствие персистентности.** Данные не сохраняются в БД — только в памяти процесса на время сессии для кнопки «сделать карточку». Это чуть менее отказоустойчиво при перезапуске бота (карточку придётся пересчитать), но проще и приватнее: никаких данных о теле пользователей на диске.
9. **Шрифты лежат в репозитории** (`fonts/`), путь задан относительно `design.py` — одинаково работает на Windows и на Linux-хостинге. Если файла нет, бот не падает, а пишет ошибку в лог.

10. **КБЖУ до 18 лет:** считается любая цель, но формула выведена на взрослых — бот предупреждает об этом, а на сушке советует согласовать дефицит с врачом.
